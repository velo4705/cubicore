Questions

How is Cubicore different from just asking opencode?

Without Cubicore, one capable agent does everything, sequentially, with no mechanical checks and no bounded scope. With Cubicore, work is split, each piece is gated by checks that can actually fail, and the factory refuses to ship failures. The output gets better and the team avoids the shared-foo-calls trap.

What is the factory-fit question?

Before any dispatch, Cubicore sizes the task: contracts, dependency edges, write scopes. If the job does not deserve a team, Cubicore says so, usually by proposing a single agent or refusing. When it does, it writes a plan and asks one question:

Dispatch as a team of N, or single agent?

Answering the form switches the plan to the mode you chose without a second prompt.

Does it work without git?

It initialises a git repository on first use in the project. Without git, diffs cannot be attributed and no scope gate can run. The output degrades to nothing verified, and Cubicore says that out loud rather than claiming a pass.

Which agents can call /cubicore?

opencode is the reference host and the only fully working one right now. The MCP registers globally in your opencode config, so any session can call the commands.

What does it cost?

Each sub-agent is a fraction of a frontier run. The plan decides how many run at all. A tiny prompt may dispatch zero companions, and should. Token usage and the factory verdict are printed in the run output.

What do I need installed?

opencode. Optionally bun for the MCP host. Cubicore installs its own runtime; you never edit your opencode config by hand.

Something is off. How do I fix it?

/cubicore:status shows what Cubicore sees per directory. For a fresh install that misbehaves, re-run npx cubicore@latest setup and restart opencode fully.

Where is the source? Can I contribute?

github.com/velo4705/cubicore. See CONTRIBUTING.md. This project does not hide that the evidence for some of its claims is thin; complain loudly if it tells you otherwise.
