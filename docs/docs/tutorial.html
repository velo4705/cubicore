C cubicore tutorial
Live session
cubicore plan-demo reads the repo, asks for scope, and writes CUBICORE_PLAN.json.
The planner splits the work into disjoint contracts and emits one brief per associate into CUBICORE_ASSOCIATES/.
Associates run in parallel and report separately, while each scope is gated by Schema → Verify → Scope.
A failed check triggers /cubicore:debug, which reviews, fixes, and re-tests until the check is green.
The app serves HTTP 200 and a deployment handoff is written for the next stage.
1

Plan

The planner identifies independent units of work and rejects collisions before execution begins.

2

Design

Each associate receives a contract: a scoped brief, checkpoints, and a narrow validation target.

3

Execute

Worktrees are isolated so each worker can move quickly without stepping on another contract.

4

Debug

Mechanical checks catch errors early. When a check fails, the loop repairs and re-runs until green.

5

Deploy

The final handoff includes the verified build, deployment notes, and serving status for the target environment.
